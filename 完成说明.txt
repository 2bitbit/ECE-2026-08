一、项目目标（一句话）
-----------------------------------------------------------------
训练一个小型卷积网络识别热轧带钢表面的 6 类缺陷，导出 ONNX 并做 int8
静态量化，证明模型能满足树莓派 5 的单件 15 ms 延迟预算。

  6 类缺陷：crazing / inclusion / patches / pitted_surface /
            rolled-in_scale / scratches


二、已完成的全部工作
-----------------------------------------------------------------

1. 环境搭建
   - 在项目目录下创建了 .venv 虚拟环境。
   - 安装了 CPU 版依赖：torch 2.13.0、onnx 1.22.0、onnxruntime 1.28.0、
     pillow、numpy、matplotlib。
   - verify.py 现在输出 PASS。

2. 数据集
   - 使用官方 NEU surface defect database：共 1800 张灰度图（200×200），
     每类 300 张，6 类完全均衡。
   - 原始文件为缩写命名的 .bmp（Cr/In/Pa/PS/RS/Sc），已映射为全类名并整理成
     NEU-DET/<类名>/ 目录结构，加载器同时兼容 .bmp 和 .jpg。

3. starter_p1.py —— 补齐 6 个 TODO（6/6 通过 --check）
   - 任务 1：像素归一化（除以 255，缩到 0~1）。
   - 任务 2：训练/测试 80/20 切分。
   - 任务 3：准确率计算（preds == truth 的均值）。
   - 任务 4：补全最后一层 nn.Linear(n_features, 6)。
   - 任务 5：训练步的 loss.backward() 和 opt.step()。
   - 任务 6：计时（perf_counter 差值 × 1000 转毫秒）。
   - 额外修复：load_real() 原先会把同一张图重复计数（导致同一张图同时进入
     训练和测试，造成泄漏），已用集合去重修复。

4. pipeline.py —— 新建的完整交付流水线（一条命令跑通）
   流程：加载数据 → 按类 60/20/20 分层切分 → 训练 float32 基线
        → 导出 ONNX 并验证一致 → 单线程 batch=1 测延迟
        → int8 静态量化 → 每类 precision/recall → 生成验收表与图表。

五、量化决策（每一项都记录了理由，用于答辩第 5 页；per-channel/per-tensor
   对照即简报「chosen with a reason, not a default」评分项）
-----------------------------------------------------------------
- 校准集：120 张（每类 20 张），全部取自训练集，不碰测试集。
- 校准方法：percentile 百分位截断，忽略异常像素，避免拉伸范围浪费精度。
- 权重：per-channel（逐通道）QInt8，每个卷积核单独一个 scale。实测 per-tensor 对照：per-channel 0.8250 vs per-tensor 0.8306，仅差 2 张测试图（噪声量级），说明「per-channel 精度更高」的假设在这个 11.5 万参数小模型上并未显现，两者可互换；保留 per-channel 作为常规选择（见 compare_per_channel.py，配图 figures/perchannel_ab.png）。
- 激活：QUInt8 非对称，因 ReLU 输出 ≥ 0，无符号范围不浪费负半轴。


六、三条「诚实」结论（答辩第 7、8 页素材）
-----------------------------------------------------------------
1. int8 把模型缩小约 4 倍，但延迟反而变慢（0.33 → 1.14 ms）。
   原因：模型太小，量化/反量化开销占主导，且本机 x86 CPU 无 int8 加速
   指令；两者都远低于 15 ms 预算。
2. 量化后掉得最多的是 pitted_surface（recall 0.817 → 0.700），因它与
   patches 视觉相近，量化模糊了细小凹坑细节。
3. 基线最弱类是 scratches（recall 0.65），因 200×200 缩到 96×96 抹掉了
   细划痕纹理；量化后它仍是 recall 最低的类。

八、如何在新电脑上复现（一条命令跑通）
-----------------------------------------------------------------
  前提：安装 Python 3.10+（Windows 勾选 Add Python to PATH），并把整个
        项目文件夹（含 NEU-DET/ 数据集）拷贝到新电脑，不要拷贝 .venv。

  cd Project_1_CQL
  python -m venv .venv
  .venv\Scripts\activate                                    （Windows）
  pip install torch --index-url https://download.pytorch.org/whl/cpu
  pip install -r requirements.txt
  python verify.py                                          （应输出 PASS）
  python pipeline.py                                        （一条命令，重新生成全部输出）

  说明：测试准确率因固定随机种子（seed=0）可精确复现；延迟取决于新机器
        的 CPU，会略有不同，但两者都远低于 15 ms 预算，判定仍为 FITS。


九、注意事项与待办
-----------------------------------------------------------------
注意事项：
- 延迟是在开发笔记本上测的（单线程、batch=1），这正是简报要求的「仿真」；
  并非真实树莓派。实际 Pi 5（ARM）上 int8 可能反而更快。
- 测试准确率是单次固定随机种子（seed=0）的结果；重跑会得到完全一致的数字。
